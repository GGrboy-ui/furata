# 位置变化但板端速度为零：只读诊断（2026-10-31）

现象：实际位置变化，网页板端速度始终为零，转臂有时单方向加速。实物根因尚未确认；当前不能将其归结为 PID 偏小，也不能宣布测速已经修复。先用 K4 停机，排查有效速度反馈。

## 本次已验证

- 未强制速度值的真实 A/B 板级 RTL 仿真：A/B → 编码器累计位置 → Q16.16 测速 → 物理 UART @W 回复 → 实际网页解析，速度均能非零。
- 当前综合网表加 Gowin 器件原语仿真：有效 A/B 正向累计有非零速度；注入正常周期数值后，除法和滤波能得到约 20 counts/s，未出现恒零。
- 原有测试主要分开覆盖真实编码器、速度控制和串口；本次额外串起真实 A/B 到速度回复，避免只用强制反馈值验证回传。
- 网页增加被动原始收发诊断，12/12 网页测试和浏览器导出验证通过。导出不会发送运动命令、不写 PID，不修改 FPGA 固件。

这些测试未复现用户实物故障，不能代替板上日志。

## 采集方法

1. 按 K4 停机，再刷新本工程网页 http://localhost:8767/（Ctrl+F5），确认出现“速度反馈诊断 · 只读记录”。不按 K1/K2，不执行轨迹。
2. 连接串口，点击“开始回传 P”，等待诊断区收到 @W/@V 速度帧。
3. 手动向同一方向连续转臂约 30～60°，用时约 2～5 秒，观察转动过程中的位置与速度。408 counts/圈时，位置应同方向累计变化约 34～68 counts。停住超过 1 秒后速度归零属于当前设计行为。
4. 点击“导出串口诊断 JSON”，保留整个文件。该记录在停机和断线后继续保留，不依赖执行运动任务，也不使用已经结束的任务 CSV。

JSON 含原始 @W/@V、位置遥测、请求及参数回读、网页地址、收发时间及连接编号，最多保留最近 20000 条。速度字段为有符号 Q16.16 counts/s；@W 的实际速度为逗号分隔第 15 项（下标 14），诊断区同时显示原始十六进制和单位换算。

## 如何区分

- 原始 actual 非零、图上零：网页版本、解析、刷新或绘图问题。
- 连续同向累计多个计数、原始 actual 仍全零：继续查实物测速、有效脉冲方向／周期、采样触发及实际下载固件。
- 位置只在相邻计数间跳动：可能 A/B 单路缺失、接触或干扰，换向会重建周期；不能仅凭“位置会变”认定两路编码器正常。
- 相邻有效脉冲间隔超过 1 秒：当前周期测速会超时并重新建立周期，极低速时可能读零。
- 未收到新速度帧：先查能力识别和查询回复，不能把过期的零值当成实时测速。

若控制器确实读取零速度，转动中的速度误差及积分可能持续增加，导致与参考轨迹不符或单向加速；在确认反馈链路前不通过增大增益或 t 掩盖问题。
