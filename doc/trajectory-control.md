## 使用

1. 下载本次发布目录的 `furata.trajectory.fs`，刷新 8766 页面。服务根目录必须为本工程 `web`。
2. 连接 USB 串口，默认 115200 / 8N1。确认识别 TRJ1。P/Q 仍只控制角度、PWM 和位置遥测。
3. 位置环更新周期默认 50 ms。填写 1～1000 的整数并点“应用周期”，以板端实际回读为准。
4. 停机或直立平衡空闲时允许设置。平衡空闲时等待原位置环的下一次更新完成，再切换新周期；不清除 PID 积分、历史误差或目标。修改期间禁止开始运动。
5. 停机时先在网页点击“应用参数并进入速度环”，核对板端回读，再按实体 K3 进入平衡，选择轨迹并检查规划预览。首次使用默认小幅、较长用时；执行期间平衡控制始终运行。
6. 规划到终点不等于实际到位。最终目标保持不动，实际误差连续 200 ms 不超过 2 counts 才报告到位。按默认 408 counts/圈，2 counts 约 1.76°；0.1° 仅为指令分辨率。
7. X 或实体 K4 停机。停止或 K4 保留已生效周期，系统复位或上电恢复编译默认。串口重连读取板端值，不自动应用输入框内容，也不恢复任务。

位置环周期独立于轨迹移动用时。角度环仍为原 5 ms；当前离散 KI、KD 和每次位置更新的积分衰减均不自动换算，改变周期会改变它们的实际时间尺度，需重新评估调参。

## 曲线定义

所有目标偏移相对本次接受任务时捕获的实际位置。连续累计位置不按整圈取模。完整参考行程须在本次进入平衡原点的 ±10 圈内，超界整条拒绝。正负方向沿用 CW_POSITIVE、ENCODER_INVERT、MOTOR_INVERT。

- 模式 1：五次多项式，`p(s)=10s³−15s⁴+6s⁵`。默认 +15° / 4 s。起终点速度与加速度为零。
- 模式 2：`A*w(t)*sin(2πt/P)`。默认幅值 15°、周期 12 s、3 周期。首半周期 `w=p(2t/P)`，末半周期 `w=p(2*(NP−t)/P)`，中间为 1；起终点位置、速度和加速度连续。最后回到任务起点。
- 模式 3：最多 8 个相对任务起点的目标点，以五次多项式连接。默认 +15°, 0°, −15°, 0°，每段 4 s、各停留 2 s，包含最后一点的停留。中间点按固定时间推进，不把参考停留当作实际到位确认。
- 模式 4：七段恒定加加速度，时长比例 1:1:1:2:1:1:1，符号为 +、0、−、0、−、0、+，根据总位移和用时缩放。默认 +15° / 4 s。

移动/周期 500～600000 ms，停留 0～600000 ms，正弦次数 1～100，角度 −36000～+36000（0.1°）。正弦幅值必须正数，其余模式周期数须为 1，非多点停留须为 0。
板端和网页检查峰值参考速度上限（默认 30°/s）：五次为 `1.875*|D|/T`，S 形为 `1.6*|D|/T`，包络正弦采用上界 `6.284*A/P`。多点逐段检查，包括从任务起点到第一点。

FPGA 使用 Q8.24 归一化曲线、分时乘法、顺序除法及 1024 分区线性插值正弦表，最终输出 Q16.16 编码器位置/速度。运算在每个 1 ms 节拍后少量系统时钟内完成；不使用浏览器计时驱动电机。

## 串口接口

请求为 ASCII 十进制，LF 或 CRLF 结尾，不超过 192 字节，整行限时 200 ms。编号 1～65535，运动角度必须带正负号。完整接收和校验前不产生运动。

```text
@TI\n                                查询 TRJ1 能力
@TQ\n                                查询最近结果与任务状态
@TC,1,20\n                           将位置环周期设为 20 ms
@T,2,1,4000,0,1,1,+150\n              五次：+15°，4 s
@T,3,2,12000,0,3,1,+150\n             正弦：15°幅值，12 s周期，3次
@T,4,3,4000,2000,1,4,+150,+0,-150,+0\n 多点：各移动4 s、停留2 s
@T,5,4,4000,0,1,1,-150\n              S形：−15°，4 s
X                                    立即停机，包括残缺命令内
```

任务公共字段为 `@T,id,mode,time_ms,dwell_ms,cycles,count,angles...`。同一任务编号不重复执行；忙、待到位或周期尚未生效时拒绝新运动。运行任务、起摆、电机测试、故障状态拒绝周期修改。设置回复在真正生效后发送，不提前报告成功。

回复字段为大写定长十六进制，CRLF 结束：

```text
@I,TRJ1,cpr4,limit4,maxspeed4,default_period4
@T,id4,code2,state1,phase1,mode1,period4,elapsed8,total8,actual8,target8,velocity8,goal8,point1,task_period4,active_id4
```

位置 actual 为有符号整数 counts；target、goal 为有符号 Q16.16 counts，velocity 为有符号 Q16.16 counts/s；时间为 ms，point 从 0 开始。period 为当前周期，task_period 是任务启动时的周期。回复固定 29 / 89 字节。
phase：0 空闲、1 整条校验、2 执行、3 等待实际到位、4 到位保持、5 取消。code：00 状态、01 接受、02 到位、03 取消、04 周期生效、10 忙、11 状态不允许、12 参数/速度/行程超界、13 格式/超时、14 重复编号。
网页最多每 250 ms 查询一次；板端状态查询按 200 ms 合并限速，接受、拒绝、完成和周期设置确认不延迟。回复只在完整遥测帧之间发送，遥测期间保留序号缺口。请求不确定时只查询，不自动重发。

旧 ARM1 的 `@I/@Q/@M` 与单字节 P/Q/X 继续可用，运动共享忙状态。超时行尾的 S/C/P/Q 不得逃逸成单字节指令，丢弃到换行或新的 @，X 始终优先。旧固件不开放 TRJ1 功能。

## 图表与导出

规划图是理想参考，不是实测；板端参考图为低频任务状态采样。实际位置来自编码器，估算速度使用最近 200 ms 同会话位置的线性拟合，少于 50 ms 数据时不显示速度；低速计数量化仍存在。
普通 CSV 保持原格式及旧格式导入兼容。任务 CSV 是独立格式，含任务配置 JSON、实际周期、状态、板端时间和当前保留的对应遥测；不通过普通 CSV 导入入口导入。
网页最多保留 20000 条任务状态，超出后保留最近部分并在导出标注；普通遥测仍最多 120000 样本。浏览器接收时刻不被冒充为板端同步时间，状态记录单独保存对应的最新遥测时间。
