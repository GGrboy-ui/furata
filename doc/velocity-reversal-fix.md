# 速度反馈换向清零修复（2026-10-31）

## 改动范围

测速算法修改于 `src/rtl/velocity_feedback.v`；`acg720_top.v` 的 OLED 三路输入、`control_core.v` 的速度位置修正采样增加一个 50 MHz 时钟（20 ns）的寄存分隔，以满足时序。OLED 三路坐标保持同拍，即时停机和行程保护不增加延迟。`speed_outer.v` 将除法结果的符号处理、积分累加和微分滤波限幅分拍完成，计算多 4 个时钟（80 ns），数值算法和毫秒采样周期保持不变。编码器位置计数、旧测速输出、方向约定、K1/K2、两套 PID 参数、角度内环、t、行程保护与协议保持原接口。低通仍为原固定约 40 ms，本次不通过调增益或减小滤波掩盖测速丢失。

## 新的测速流程

1. 每个有效 A/B 跳变仍由编码器解码为 +1 或 −1。测速模块先按实际 1 ms 采样节拍累计净增量；同一窗口内的 +1/−1 对消，不把短促返回跳变当作高速运动。位置通道本身没有增加这一窗口或改变计数。
2. 第一个非零窗口建立基准；之后每个非零窗口，无论是否换向，都建立新的带符号周期。周期计数使用系统时钟，速度 Q16.16 = 窗口净计数绝对值 × CLK_HZ × 65536 / 周期时钟数，符号来自净增量。
3. 换向只改变后续测速样本的符号，不清空原始速度或滤波历史。40 ms 低通连续更新，允许速度平滑穿过零；因此滤波反馈不会在物理换向的一瞬间立即反号。
4. 新测量到来后，尚未完成的旧计算失效；一个失效任务不会因为再次换向而恢复有效。新的方向结果只在完整计算后提交。编码器组合信号不再作为除法器的异步复位。
5. 无新净位移且等待时间超过上次周期时按等待时间降低估计，最后一个非零窗口后约 1 秒强制归零、丢弃旧周期与计算任务；重新移动后第一窗口建立基准，第二窗口可在任意方向建立周期。

多个净计数发生在一个窗口时计入幅值，持续运动不会因为每毫秒都有新测量而把所有计算永久取消。窗口计数采用有界饱和，测速输出保留原有范围和定点单位。

## 验证重点

同样 40 次单计数交替往返：旧版本 0/40 次非零，新版本 39/40 次非零（首次建立基准为零）。新增回归覆盖单计数频繁换向、首次反向响应、滤波连续过零、1 ms 内净零跳变、采样边界、每毫秒多个计数、计算中多次换向取消旧结果、停止超时及真实 A/B 到物理 @W UART 回复。

窗口内净位移为零或低通穿过零时，反馈仍可以合理地为零；本修复消除的是每遇一次方向变化就把全部测速历史强制清掉。编码器分辨率、实际电气干扰和机械振动仍须用板上数据核对。

速度 PID 时序分拍另做 200 组新旧数值对照，覆盖零增益、满范围带符号输入、饱和、复位及 5～100 ms 周期；数值结果保持一致。

## 实物复验

先 K4 停机，再下载本版发布文件；下载后继续保持停机，通过网页“速度反馈诊断”手动低速正反转臂并导出 JSON。下载会恢复上电默认参数，先在网页核对板端实际配置。确认换向过程有连续、有符号的反馈后，再进行小幅平衡及轨迹实验。若发生异常加速立即 K4 停机。本次不自动烧录，不宣称实物轨迹误差已改善。
